# ADR-005: UUID primary keys

- Status: Accepted
- Date: 2026-10-26

## Context

IDs appear in URLs. Sequential integers reveal business volume and invite enumeration (`/orders/1001`, `/orders/1002`). Modules may later become separate services that must create IDs independently.

## Decision

Use `UUID` primary keys, generated by the application as time-ordered UUID version 7.

## Alternatives considered

| Option | Trade-off |
|---|---|
| `BIGSERIAL` | Smallest and fastest, but guessable and tied to one database |
| Random UUID v4 | Not guessable, but random inserts fragment B-tree indexes |
| ULID / Snowflake | Similar benefits; less native support in PostgreSQL and Hibernate |

## Consequences

- 16 bytes per key instead of 8; acceptable at our scale.
- Version 7 is time-ordered, so inserts stay close to the end of the index like a sequence.
- IDs can be generated before insert, which simplifies events and batching.
- Authorization is still required on every resource; UUIDs are not a security control by themselves.
